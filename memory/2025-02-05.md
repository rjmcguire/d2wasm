# 2025-02-05 - Native Backend Parity & CTFEContext Refactor

## Session Summary

Major work on native CTFE backend - achieved feature parity with WASM for slice operations, refactored host function architecture.

## Changes Made

### 1. test_runner.sh Fix
- Added validation of `expected_result` from config.json (not just expected.txt)
- 35 tests were silently passing without validation before this fix

### 2. Arena CTFE Bug Fix
- **Problem:** CTFE ran twice for same manifest constant (type checking + manifest eval)
- **Wrong fix attempted:** Reset arena between evaluations
- **Correct fix:** `ctfeComplete` guard in `evaluateManifestConstant()` - evaluate once, cache result
- Arena doesn't reset between evals - that's correct for lazy CTFE model

### 3. Native `~=` (Slice Append) Implementation
- Added `__ctfe_alloc` host function for native heap allocation
- Implemented `compileSliceAppend()` in backend.d (~150 lines)
- Mirrors WASM emitter logic: capacity check, grow if needed, copy, store element, increment length
- Uses temp slots from pre-allocated frame space (not relative to slice offset!)

### 4. Binary Expression Fixes
- **IndexExpression clobbering:** Added to `leftMightClobber` check - index expressions use x1 internally
- **Nested tempSlot clobbering:** Added `tempSlotDepth` counter - each nesting level uses different temp offset

### 5. CTFEContext Refactor (Milestones 90-91)
- Created `CTFEContext` struct with `dataSection` pointer
- Updated `HostFunctionTable` to store context, provide slot address
- Added `emitHostCall()` that injects context to x0, shifts args to x1-x3
- Updated all host function signatures: `(CTFEContext*, long, long, long)`
- **Removed global `g_activeDataSection`** - clean dependency injection

## Test Results

## Lessons Learned
- Arena reset doesn't fit lazy CTFE model - each eval should be independent via caching, not resetting
- Test infrastructure bugs can hide real failures (35 tests weren't validating!)
- Register clobbering in complex expressions requires careful tracking
- Global state → dependency injection is cleaner, but adds calling overhead (fixable)
